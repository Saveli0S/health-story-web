# Лабораторные бланки

Пять синтетических документов относятся к одному вымышленному пациенту «Лада Макетова, QA-17». Материал образца, результаты, референсы и даты заданы специально для теста. Все реквизиты и значения для сверки указаны в [expected.json](expected.json). Можно загружать документы по очереди через «Анализы → Загрузить бланк».

| --- | --- | --- |
| [01-baseline.pdf](01-baseline.pdf) | Русский табличный PDF, десятичная запятая, пороговый результат и две даты | Точно перенесены все 3 строки, диапазоны, биоматериалы и дата взятия. |

## Что изменилось после первой проверки

При первой загрузке приложение точно перенесло 5 из 11 строк. Оно смешивало глюкозу плазмы и мочи, разделяло синонимы гемоглобина, пропускало качественный результат и референсы с отдельной строки. При повторной загрузке всех пяти файлов в обоих браузерах тест сохранил исходные поля прямо из формы. С эталоном совпали 11 из 11 строк, включая биоматериалы, и все 15 реквизитов бланков.

- У гемоглобина одна серия 132 → 138 → 140 г/л для трёх исходных форматов. Для каждого значения доступен оригинал с исходными единицами.
- У глюкозы плазмы отдельная серия 4,8 → 5,1 → 5,0 ммоль/л. У глюкозы мочи одна точка 0,3 ммоль/л. [График в Chrome](glucose-trend-chrome.png) · [График в WebKit](glucose-trend-webkit.png).
- «<1» и «отрицательно» остаются в исходных бланках и списке по датам. График строится по числовым точкам. Во всех восьми проверенных переходах с точки открылся нужный файл.
- Через кнопку «Обсудить с ИИ» проверены две реальные сводки до отправки. В запрос для гемоглобина попали исходные значения и пересчёт в г/л. В запрос для мочи попали результаты мочи без точек плазмы.
- Для документов без установленного биоматериала сравнение ограничено одним бланком. Исходные диапазоны указываются в единицах бланка. Написания и единицы без известного соответствия остаются отдельными. Сверенный биоматериал можно внести в каждой строке вручную.

## Воспроизведение

Запустите локальный сервер из корня проекта. Для теста нужны Node.js, доступный пакет playwright-core, Chrome и WebKit соответствующей версии. Новый контекст браузера изолирован, запросы за пределы origin приложения блокируются. Используется штатная форма загрузки, обработчики OCR, график и кнопки интерфейса. Запросов внешнему ИИ нет.

```sh
python3 serve_preview.py --port 8764
```

В другом терминале из корня проекта выполните команды. Переменная HEALTH_PREVIEW_URL позволяет выбрать другой локальный адрес. Опция --record обновляет JSON с наблюдениями и снимок графика в этой папке. Код завершения 1 означает расхождение с эталоном, 2 — ошибку выполнения сценария.

```sh
node tests/medical-corpus/labs/check.cjs --record
node tests/medical-corpus/labs/check.cjs --iphone --record
```

Первый прогон использует настольный Chrome, второй — движок WebKit с параметрами iPhone 13. [Отчёт Chrome](observed-chrome.json) · [Отчёт WebKit](observed-webkit.json). Даты и текст считаны из формы сверки до подтверждения. Показатели, реквизиты и биоматериалы в этом прогоне не редактировались. Проверка iOS-приложения в этот прогон не входит.

Проверка несовместимых единиц, конфликтующих дат и старых записей выполняется командой `node --test tests/medical-corpus/labs/series.test.cjs`.
