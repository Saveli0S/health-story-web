# Визиты четырёх вымышленных клиник

В каталоге пять оригиналов для четырёх визитов. Имена, препараты и назначения вымышлены для проверки интерфейса. V03 создан с помощью ImageGen и содержит имитацию рукописи синей ручкой. Эталон составлен по видимому содержимому готовых файлов. У JPEG V04 есть только пиксели, у обоих PDF есть текстовый слой.

| Случай | Как загрузить | Особенность |
| --- | --- | --- |
| V01 | V01-visit.pdf | Одностраничный бланк с подписями полей, датами рождения и приёма |
| V02 | V02-two-page-visit.pdf | Другая клиника и врач. Дата приёма записана словами. Дата печати дубликата указана цифрами. Назначение и рекомендации на странице 2 |
| V03 | V03-handwriting.png | Снимок рукописного листа. На оригинале «Дермотест, ? мг». Имя пациента, специальность, название визита, числовая доза и схема отсутствуют |
| V04 | Выбрать V04-a-front.jpg и V04-b-advice.jpg одновременно | На первом листе осмотр и назначение. Второй содержит рекомендации |

## Результаты повторной проверки

26 ноября 2026 года каждый комплект загрузили через «Новый визит → По фото или PDF → Распознать на устройстве». Chrome на компьютере и WebKit с параметрами iPhone 13 дали одинаковые результаты. Каждый сценарий работал в чистом браузерном профиле. Ошибок JavaScript на странице и запросов к внешним HTTP-серверам не зарегистрировано.

Три печатных комплекта полностью совпали с исходным эталоном до ручного вмешательства. В V02 выбрана дата осмотра 19.03.2026, а 25.03.2026 осталась датой печати в оригинале. В V04 распознаны клиника, ясная доза и название лекарства, открылись оба JPEG. После сохранения и повторного входа рекомендации и оба оригинала доступны. Изменение клиники именно этого визита сохранилось после перезагрузки.

### Рукопись и обязательное уточнение

На V03 исходный веб-OCR не извлёк надёжных полей. Тестер открыл оригинал, получил подсказки для ручного ввода и отложил назначение. Доза осталась пустой, разбор был заблокирован. В отдельном проходе ввели читаемые строки через «Исправить распознанный текст». На этапе сверки появились врач, дата, клиника, диагноз, жалобы, название «Дермотест» и рекомендации. Исходные фото и OCR-текст сохранились.

Пока в дозе стояло «? мг», подтвердить назначение и перейти к анализу было нельзя. После ввода тестовой дозы, отдельно уточнённой для этого сценария, точка вместо схемы также блокировала подтверждение. После явного ввода схемы и подтверждения открылась возможность передать визит на анализ. Никаких данных провайдеру тест не отправлял.

В отдельном опыте на одном V03 сравнили пять проходов локального Tesseract. Штатный вариант и PSM 6 дали среднюю уверенность 43, PSM 11 — 35. Выделение синих чернил с PSM 6 дало 43, с PSM 11 — 44. В одной обработке появился знак вопроса из дозы, в другой — похожая на дату строка. Ни один вариант не распознал достоверно весь препарат и схему. Эти показатели характеризуют только этот файл. Режим приложения оставлен штатным. [Результаты эксперимента](ocr-modes-results.json)

### Анамнез и совместимость

Дополнительный текстовый бланк с аллергией на «Макетин», отменённым «Архивином» и текущим «Листином» даёт одну активную строку. Информация из анамнеза и отмен сохраняется в оригинале и доступна при сверке. У названия формы и схемы отдельные поля. При низкой уверенности OCR в цифре или единице дозировки препарат требует ручного уточнения.

На сохранённом по прежним правилам черновике проверили пересчёт автоматических полей и списка препаратов. Введённое ранее пользователем название и отложенная правка препарата сохранились при повторном открытии. Пользователь может явно заменить поля из исходного или исправленного текста. У проверенного назначения прежняя запись сохраняется.

## Как повторить

Из корня проекта запустите локальное приложение и затем выполните команды в окружении с playwright-core, Chrome и браузером Playwright WebKit.

```sh
node tests/medical-corpus/visits/check.cjs
node tests/medical-corpus/visits/check.cjs --iphone
node tests/medical-corpus/visits/check.cjs --strict-ocr
node tests/medical-corpus/visits/legacy.cjs
node --test tests/medical-corpus/visits/parser.test.cjs
node tests/medical-corpus/visits/ocr-modes.cjs
```

По умолчанию тест открывает http://127.0.0.1:8764/. Другой адрес можно указать через HEALTH_PREVIEW_URL. В штатном режиме скрипт требует полного совпадения для печатных документов. Для рукописного примера допускается пропуск, только если сомнительные сведения заблокированы и пользователь смог уточнить их по оригиналу. Ошибочная заполненная доза, посторонняя запись или незаблокированный разбор провалят проверку.

В режиме `--strict-ocr` неполное автоматическое чтение V03 возвращает код 1. Полный эталон сохранён в [expected.json](expected.json). Фактические поля, пропуски и результаты ручной проверки перечислены в [Chrome](chrome-results.json) и [WebKit](webkit-results.json).
