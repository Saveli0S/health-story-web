# Проверки нативного приложения

На симуляторе iPhone 17 под iOS 27.2 собраны штатные конфигурации Debug и Release. Приложение со штатным идентификатором запустилось. Для автоматизации пользовательских действий отдельную копию той же программы установили под тестовым идентификатором `by.healthstory.medicalcorpus`. Учебная семья и тестовый ключ создаются скриптом внутри контейнера этого приложения.

## Распознавание 12 файлов

[Проверка](recognition.py) запускает на симуляторе код приложения из ClinicalOCR.swift и общий clinical-parser.js через JavaScriptCore. [Полный результат](observed.json) содержит поля по каждому документу и количество строк, в которых Vision отметил низкую уверенность. Значение уверенности относится к строке целиком.

- Для четырёх визитов совпали даты посещения и клиники. На рукописном листе V03 распознано название «Дермотест», дозировка и схема в черновике остались пустыми.
- В PDF с текстовым штампом поверх скана распознаны «Синдром сухого глаза», жалобы и дата 04.04.2026. Для этого файла и JPEG V04 Vision потребовал вручную сверить «2 мг».
- В первые четыре лабораторных бланка внесены десять результатов, на пятом бланке значение белка «?» сохранилось как черновик для уточнения. Все одиннадцать исходных строк соответствуют эталону по значению и единице.
- Гемоглобин из трёх бланков нормализован в одну серию. На графике 132, 138 и 140 г/л, в оригинале у второго значения 13.8 g/dL. Для глюкозы сохранились отдельные серии плазмы и мочи. Значения со знаками сравнения и словесные результаты можно прочитать в исходной строке.

## ИИ-консультация

[Нативный UI-тест](ConsultationUI.swift) открывает зашифрованную учебную семью, выбирает профиль, создаёт консультацию и включает эпизод. В предварительном просмотре проверяются анализ, измерение, вопрос к визиту, пометка и сведения из сверенного назначения. Из запроса исключены имя, email, данные другого профиля и несверенная запись. Через экран ручной передачи тест копирует подготовленный запрос и сохраняет синтетический ответ в историю. [Экран сохранённого ответа](consultation-history.webp).

Второй UI-тест открыл ранее сохранённый черновик с открытым email и подтвердил обезличивание перед ручной передачей. Для уже переданного запроса история показала исходный сохранённый текст. Итог последнего запуска — два UI-теста, оба прошли.

Внешний провайдер, камера и физический iPhone в этих автоматизированных сценариях не использовались. Распознавание проверено на фиксированном наборе бланков. Разборчивость другой рукописи требует сверки.

Для повторения запустите симулятор и подставьте его UUID из `xcrun simctl list devices booted`.

```sh
python3 tests/medical-corpus/native/recognition.py <UUID>
python3 tests/medical-corpus/native/ui-check.py <UUID>
```

[Скрипт UI-проверки](ui-check.py) выводит путь к журналам Xcode и пакету результатов .xcresult.

## Лабораторные бланки и пакет визита

Сценарий `lab` передаёт два файла на вход нативного импортёра, распознаёт бланк на устройстве, откладывает сверку и завершает её после перезапуска. На графике проверяется подтверждённый гемоглобин 132 г/л. Сценарий `batch` открывает черновик веб-формата, сверяет оба оригинала и сохраняет один визит. Для тестов используются отдельные приложения симулятора с синтетическими профилями.

```sh
python3 tests/medical-corpus/native/ui-check.py <UUID> --case lab
python3 tests/medical-corpus/native/ui-check.py <UUID> --case batch
node tests/medical-corpus/native/web-readback.cjs lab <UUID> --published
node tests/medical-corpus/native/web-readback.cjs batch <UUID> --published --iphone
```

После каждого нативного сценария веб-проверку можно запустить в Chrome и с параметром `--iphone` в WebKit. Она открывает архив в новом профиле браузера и сравнивает SHA-256 обоих вложений. Требуется установленный playwright-core с движками. При отсутствии `--published` используется локальный стенд на порту 8764.

Сценарий `pharmacy-live` использует изолированный учебный профиль и живой каталог. Он проверяет Минск, поиск по Беларуси и цену выбранной упаковки. В запросах используется только название контрольного препарата и регион. Сценарий требует доступности tabletka.by и наличия контрольной упаковки в каталоге.

```sh
python3 tests/medical-corpus/native/ui-check.py "$SIMULATOR_ID" --case pharmacy-live
```

## Проверка переписки ChatGPT в симуляторе

Запускать при открытом симуляторе iPhone. Сценарий ставит приложение в отдельный тестовый контейнер и подставляет ответы на два учебных запроса. Он проверяет HTTPS-формат, обезличенный контекст, сохранение черновика при 429, повтор, историю после перезапуска и автора отправки при чтении архива в вебе.

```sh
python3 tests/medical-corpus/native/ui-check.py "$SIMULATOR_ID" --case chatgpt
node tests/medical-corpus/native/web-readback.cjs chatgpt "$SIMULATOR_ID"
node tests/medical-corpus/native/web-readback.cjs chatgpt "$SIMULATOR_ID" --iphone
```

Сценарий `review-direct` отдельно проверяет подтверждённую передачу обезличенного разбора лечения через подставной HTTPS-транспорт, сохранение запроса после 429 и один ответ после повтора. Сценарий `visit-files` проверяет добавление рекомендации к существующему визиту и сверку. Файлы и ответы в обоих случаях учебные.

Переменная `SIMULATOR_ID` содержит UUID запущенного симулятора. Для двух последних команд нужен запущенный локальный дневник на порту 8764 и установленный Playwright. Для проверки веб-шлюза используйте `node tests/chatgpt-conversation-ui.cjs --hosted`. Флаг `--iphone` запускает мобильный WebKit.
