# Семейный сценарий

Одна новая семья с тремя профилями в каждом прогоне. Администратор создаёт записи, взрослый и ребёнок получают доступ на отдельных устройствах. После проверки архив восстанавливается в ещё одном чистом браузере. Тест использует штатные формы, кнопки, скачивание и выбор файлов. Сервер локальный, все медицинские сведения синтетические.

| Путь | Что подтверждено |
| --- | --- |
| Настольный Chrome → мобильный WebKit | Создание семьи и медицинских записей в Chrome, подключение ребёнка и взрослого в изолированных контекстах WebKit, восстановление в третьем чистом контексте WebKit. [Результат](chrome.json) |
| Мобильный WebKit → настольный Chrome | Тот же сценарий с обратным направлением переноса. WebKit использует параметры iPhone 13. [Результат](webkit.json) |
| Chrome ↔ WebKit через локальный сервер обмена | Независимые и конфликтующие правки, выбор значения с учётом автора, доставка оригинала, наследование доступа к новым детям, отзыв устройства и смена ключа. Вторая проверка охватывает зашифрованное локальное хранение, права и повреждённый пакет доступа. [Вывод двух проверок](device-checks.txt) |

В каждом основном прогоне проверяются:

1. Профили администратора, взрослого и ребёнка. Рост, вес, дата измерений, аллергия, создание, изменение и удаление дополнительного поля.
2. Взрослый профиль с визитом из PDF. Сверены дата, клиника, препарат, дозировка и рекомендации.
3. Детский эпизод с двумя врачами и двумя препаратами. Проверены даты приёма, авторская пометка, отмена одного назначения, продолжение и последующее завершение другого, сохранение в истории.
4. Три лабораторных документа. Для результата из английского PDF сохранено 13.8 g/dL; на общем графике точки 132 и 138 г/л. Глюкоза мочи открывается отдельным рядом.
5. Инструментальное обследование с заключением из PDF и отдельным изображением. Они доступны из визита, обследование входит в сводку.
6. Состав запроса на разбор лечения с историей аллергии, препаратами, лабораторными и инструментальными результатами. Для проверки истории записан вручную введённый ответ. Все сетевые обращения за пределы локального приложения блокируются и проверяются.
7. Домашние измерения с графиком, прививка с привязкой к визиту и отдельная консультация, содержащая только выбранную профилактическую запись. В сводке к приёму сохранён вопрос врачу.
8. Подключение ребёнка, которому видны свой профиль и общая пометка. Подключение взрослого, которому доступны свой профиль и редактирование карты ребёнка.
9. Экспорт единого зашифрованного архива и восстановление на чистом устройстве. Проверены все три профиля, история визитов и побайтовое совпадение шести оригиналов по SHA-256 через штатное скачивание. После восстановления администратор подключает новые устройства взрослого и ребёнка. Проверяются видимость профилей, доступ к редактированию и SHA-256 снимка на устройстве ребёнка.

Проверки обмена запускаются отдельно и создают собственные синтетические семьи; для моделирования конфликтов и проверки состояния зашифрованного хранилища они также обращаются к API приложения. Физический iPhone, внешние облачные диски, фактические цены и медицинские выводы реального ИИ в этом прогоне не проверяются.

## Повторный запуск

Из корня проекта запустите локальный сайт на порту 8764 и сервер обмена на 8765 с отдельной тестовой SQLite-базой вне каталога проекта. Каждый сервер работает в своём терминале. Для тестов нужны доступный пакет playwright-core, Chrome и соответствующая версия Playwright WebKit.

```sh
python3 serve_preview.py --port 8764
python3 serve_preview.py --port 8765 --sync-store /tmp/health-story-family-scenario.sqlite
```

```sh
node tests/family-scenario-ui.cjs --record
node tests/family-scenario-ui.cjs --iphone --record
node tests/device-vault-ui.cjs --mixed
node tests/sync-ui.cjs
```

Основной сценарий делает запросы только к локальному адресу. Ключ восстановления и одноразовые коды подключения хранятся в памяти процесса проверки. В JSON записаны результаты шагов и контрольные суммы синтетических источников.
