# Проверка медицинских документов

26 ноября 2026. Локальная рабочая версия «Лист здоровья». Три независимых агента подготовили визиты, анализы и вложения. Добавлены отдельные примеры для проверки контекста назначения, неполного текстового слоя PDF и данных для ИИ. Все данные вымышлены. Результаты относятся к конкретным бланкам в наборе.

## Как попробовать самостоятельно

Откройте [опубликованное веб-приложение](https://saveli0s.github.io/health-story-web/) в отдельном профиле браузера. Для локального прогона доступен [стенд на компьютере](http://127.0.0.1:8764/). [Скачать 18 тестовых файлов с инструкцией и эталонами](../../previews/medical-test-documents.zip). Распакуйте архив. Вложения для загрузки лежат в папках visits, labs и attachments/files. В context также есть примеры для ручного ввода.

1. Откройте «Новый визит → По фото или PDF → Распознать на устройстве». Выберите V02-two-page-visit.pdf. Переключитесь на вторую страницу, сравните назначение. Визит был **19 марта 2026**, дубликат напечатан **25 марта**.
2. Для проверки рукописи создайте отдельный визит с V03-handwriting.png. На оригинале написано «Дермотест, ? мг». Доза неизвестна. Оставьте документ на уточнение. Для пакетной загрузки выберите одновременно V04-a-front.jpg и V04-b-advice.jpg.
3. В одном учебном профиле откройте «Анализы → Загрузить бланк». Загрузите 01–04 из labs по очереди. Сравните распознанные поля с labs/expected.json, исправьте расхождения и сохраните. Откройте «Динамика» у гемоглобина и глюкозы. В пятом бланке значение «?» должно остаться в черновике.
4. В учебном визите выберите «Прикрепить файл». Добавьте все пять оригиналов из attachments/files. Для ZIP выберите «Снимки». Откройте вторую страницу заключения, оба изображения, текстовую записку и скачайте DICOM.
5. Загрузите context/история-лечения.txt как новый визит. Действующее назначение одно — Листин 5 мг. В файле отдельно указаны аллергия на Макетин и отмена Архивина.
6. В context/дневник-наблюдений.json приведены данные для ввода двух измерений и прививки. В консультации выберите только эту прививку и проверьте предварительный текст запроса с вымышленными идентификаторами. Можно остановиться на сводке.

| Сценарий | Фактический результат | Критерий повторной проверки |

| Материал пробы на графике | После ручной сверки 4,8 ммоль/л глюкозы плазмы и 0,3 ммоль/л глюкозы мочи соединены одной линией | Пробы из разных материалов образуют независимые серии. При неизвестном материале приложение предлагает уточнение |

Пороговые и качественные результаты сохраняют тип |

## После обновления iOS

Штатное приложение собрано в Debug и Release для симулятора. Нативный обработчик извлёк тело гибридного PDF и сохранил сомнительную дозировку для ручной сверки. При автоматизированной проверке создана консультация, сохранён ответ, восстановлен и очищен старый черновик. Уже переданный запрос сохранил свою историю. Подписанное обновление установлено поверх приложения на физическом iPhone. Пользователь отложил проверку запуска на телефоне.

## Исходная сборка iOS и условия первого прогона

В загрузившемся симуляторе iOS 27.2 отдельно прогнаны 12 файлов через код извлечения текста из DeviceViews.swift, Apple Vision, PDFKit и общий JS-парсер приложения. Apple Vision распознал дату рукописного визита, лекарство в структурированную строку не попало. Английский PDF дал ноль лабораторных строк. На выписке iOS повторил ошибку даты дубликата. [Фактические поля на симуляторе](native/observed.json).

Сборка на момент первого прогона завершилась ошибкой компилятора в ios/HealthStory/ClinicalViews.swift, строка 16 — cannot find 'Consultations' in scope. Полный интерфейс этой версии на физическом iPhone в этом прогоне не проверен. Мобильные сквозные проверки выполнены в WebKit с параметрами iPhone 13. Ответы внешнего ИИ, Google Drive и аптечного каталога в интеграционных сценариях подставлены тестом. Реальное качество медицинской оценки, наличие препаратов на сегодня и эквивалентность аналогов этим прогоном не подтверждены. Один синтетический рукописный образец не даёт оценки точности для почерков врачей.

## Как повторить

Запустите приложение командой `python3 serve_preview.py --port 8764` из корня проекта. Для браузерных тестов нужны Node.js, доступный playwright-core, Chrome и Playwright WebKit соответствующей версии. В README каждого раздела приведены команды и ожидаемые результаты. Дополнительно можно запустить следующие проверки из корня проекта.

```sh
node tests/medical-corpus/context/check.cjs
node tests/medical-corpus/context/check.cjs --iphone
python3 tests/medical-corpus/native/recognition.py
node --test tests/intake.test.cjs tests/sync-merge.test.cjs
```

Первые две команды возвращают код 1 при расхождении с эталоном и сохраняют наблюдения. Для третьей нужен уже запущенный симулятор iOS и Xcode. Тестовые прогоны используют отдельные контексты браузера. Веб-сервер по умолчанию не раздаёт этот каталог с тестами.
